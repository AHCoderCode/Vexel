PROMPTING BASICS

How to write better AI prompts

A useful prompt reduces guesswork. You do not need secret keywords or complicated jargon; you need to explain the outcome you want, the context that matters, and how you will judge the result.

A practical guide · About 6 minutes

People often ask an AI assistant something broad, receive a broad answer, and assume the model is incapable. Sometimes that is true, but often the request left too many important choices unspecified. A prompt cannot guarantee accuracy, yet it can make the task easier to understand and the result easier to evaluate.

Use a five-part framework

Before sending a request, think through these five elements. You can leave out any element that genuinely does not matter, but consider each one deliberately.

  1. Goal: What finished result do you need? Say “help me find the bug in this function” instead of “JavaScript.”
  2. Context: What should the assistant know first? Give the intended audience, current skill level, relevant background, or a small sample of the input.
  3. Constraints: What must it avoid or preserve? Examples include “use plain JavaScript,” “do not change the HTML,” or “keep the explanation beginner-friendly.”
  4. Format: What shape should the answer take? Request numbered steps, a table, a worked example, or a patch with the exact filename.
  5. Quality check: How should the answer be checked? Ask the assistant to list assumptions, flag uncertainty, or provide a test case.

Reusable prompt template

Goal: [the result I want]
Context: [what the assistant needs to know]
Constraints: [what to include, avoid, or keep unchanged]
Format: [how I want the answer organised]
Check: [how to test or verify the result]

Do not fill every line with unnecessary detail. The aim is to share relevant information, not to make every request long.

Before and after: three examples

Example 1: learning a concept

Broad request: “Teach me loops.”

Clearer request: “Explain Python for loops to a beginner who understands variables and lists. Start with a simple everyday analogy, show two short examples, then give me three questions one at a time. Do not reveal the answer until I try.”

The second prompt gives the assistant a level, a scope, and a teaching method. It also turns reading into practice.

Example 2: improving writing

Broad request: “Make this better.”

Clearer request: “Rewrite the paragraph below for a school newsletter. Keep the meaning and all factual details, use a warm but straightforward tone, and keep it under 120 words. After the rewrite, list any facts that were ambiguous rather than inventing details.”

Notice the guardrail: preserving facts is just as important as improving style.

Example 3: fixing code

Broad request: “My website is broken.”

Clearer request: “In script.js, clicking Submit should validate the form but nothing happens. I am using plain JavaScript in a browser. Here is the relevant HTML, event listener, and exact console error. Identify the most likely cause first, explain it in beginner language, and give the smallest safe change. Do not rewrite unrelated files.”

Relevant code and an exact error are much more informative than a description of the whole project. Remove passwords, API keys, private chat logs, and personal information before sharing code or screenshots.

Improve a prompt in small iterations

If the first response misses the mark, identify what is wrong with it. “This is too advanced” or “you changed the requirement” is useful feedback; repeating the original prompt verbatim often is not.

  1. Compare the response with the original goal.
  2. Name one concrete gap, such as an incorrect assumption, missing step, or unsuitable format.
  3. Ask for a revision that addresses that gap while preserving the parts that were correct.
  4. Check the revised result rather than accepting it simply because it is the second attempt.

Common prompt mistakes

  • Too many unrelated tasks. Split a large project into a clear sequence with a definition of “done” for each stage.
  • Conflicting instructions. Saying “explain every detail” and “answer in one sentence” makes priorities unclear. State which requirement matters most.
  • Missing environment information. Programming answers can differ by language version, browser, framework, or operating system.
  • Demanding certainty. “Never be wrong” cannot ensure correctness. A request to show assumptions and verification steps is more practical.
  • Sharing sensitive data. A better prompt should not require private credentials or unnecessary personal details.

A 30-second pre-send check

  • Can a reader tell what successful completion means?
  • Have I included the context that could change the answer?
  • Have I stated important limits or things that must remain unchanged?
  • Will the chosen output format help me use the response?
  • Do I know how to test or verify the result?

A good prompt is a clear task description, not a magic spell. Start with the real goal, provide relevant context, and review the result. Over time, this habit improves collaboration with AI tools and with people, too.
